Pendahuluan 
Buku ini memandu peserta membangun dashboard interaktif berbasis Python dengan Streamlit dan Dash dalam 
8 sesi (2 hari, 16 jam), dari aplikasi pertama sampai dashboard final yang menampilkan output prediksi dari model 
Machine Learning final. Seluruh praktikum memakai satu studi kasus yang sama, Customer Churn, sehingga setiap 
sesi menambah satu lapisan pada dashboard yang sedang dibangun. 
Pelatihan ini adalah bagian dari 2nd On-the-Job Training (OJT) Technical Data Analytics, ITSB Corporation, dengan 
instruktur Bakti Siregar, M.Sc. Pendekatannya practice -first: konsep singkat, demonstrasi, hands -on, integrasi, 
proyek akhir, lalu interpretasi hasil. 
Cara memakai buku ini 
Setiap bab sesi memiliki struktur yang sama: 
1. Tujuan sesi — kemampuan yang harus dikuasai di akhir sesi. 
2. Konsep inti — penjelasan singkat sebelum menulis kode. 
3. Praktikum terpandu — langkah bernomor, kode lengkap, dan perintah untuk menjalankannya. 
4. Penjelasan kode — bagian penting dari kode dibahas baris demi baris. 
5. Checkpoint — hasil yang harus terlihat di layar sebelum lanjut. 
6. Latihan mandiri — tugas untuk dikerjakan sendiri; kunci jawaban ada di Lampiran. 
7. Kesalahan umum — pesan error yang sering muncul dan cara mengatasinya. 
 
Semua kode di buku ini sudah dijalankan dan diuji dengan Python 3.13, Streamlit 1.65, Dash 4.4, Plotly 7.1, pandas 
3.0, dan scikit-learn 1.9.1. Kode juga kompatibel dengan versi yang lebih lama sesuai requirements.txt (Streamlit 
≥ 1.40, Dash ≥ 2.17, Plotly ≥ 5.22, pandas ≥ 2.2). 
Prasyarat peserta 
• Dasar Python: variabel, list, dictionary, fungsi, if, dan for. 
• Dasar pandas: membaca CSV, memilih kolom, dan filter baris. 
• Laptop dengan Python 3.10 atau lebih baru, editor kode (VS Code disarankan), dan koneksi internet. 
• Materi ini bukan pengantar Python dari nol.

1.1 Apa itu Streamlit 
Streamlit adalah library Python open -source untuk mengubah script analisis data menjadi aplikasi web interaktif 
tanpa menulis HTML, CSS, atau JavaScript. Satu file .py sudah cukup untuk satu aplikasi.

1.2 Model eksekusi Streamlit 
Konsep terpenting di Streamlit: setiap kali pengguna mengubah widget (slider, tombol, dropdown), seluruh 
script dijalankan ulang dari baris pertama sampai terakhir.  Nilai widget terbaru dikembalikan sebagai variabel 
Python biasa. Karena itu: 
• Proses berat seperti membaca file besar atau memuat model harus di -cache ( @st.cache_data, 
@st.cache_resource) agar tidak diulang setiap interaksi. Ini dibahas di Sesi 2 dan 4. 
• Variabel biasa akan kembali ke nilai awal setiap rerun. Untuk menyimpan nilai antar -rerun gunakan

2.5 Praktikum B — Dashboard EDA interaktif di Streamlit 
Grafik Matplotlib di atas bersifat statis. Di dashboard, grafik sebaiknya interaktif: pengguna dapat mengarahkan 
kursor, memilih variabel, dan berpindah tab. Aplikasi berikut menyusun EDA menjadi KPI card dan enam tab 
(Komposisi, Perbandingan, Distribusi, Tren, Hubungan, Data) memakai Plotly Express, yang dibahas lebih dalam di 
Sesi 6. 
Buat sesi2/app_eda.py: 
 PYTHON 
# sesi2/app_eda.py — EDA interaktif di Streamlit dengan beragam visualisasi Plotly 
from pathlib import Path 
import pandas as pd 
import plotly.express as px 

PAGE 32
Buku Praktikum · Interactive Dashboard Development with Streamlit & Dash ITSB Corporation 
26 
import streamlit as st 
  
ROOT = Path(__file__).resolve().parents[1] 
st.set_page_config(page_title="EDA Churn", page_icon="🔎", layout="wide") 
  
STATUS = {"Bertahan": "#2a78d6", "Churn": "#eb6834"} 
KATEGORI = ["#2a78d6", "#1baf7a", "#eda100", "#4a3aa7", "#e87ba4"] 
KONTRAK = ["Bulanan", "Tahunan", "Dua Tahun"] 
  
@st.cache_data 
def load_data(): 
    df = pd.read_csv(ROOT / "data" / "customer_churn.csv", parse_dates=["signup_date"]) 
    df["total_charges_missing"] = df["total_charges"].isna()        # catat sebelum imputasi 
    df["total_charges"] = df["total_charges"].fillna(df["total_charges"].median()) 
    df["status"] = df["churn"].map({0: "Bertahan", 1: "Churn"}) 
    df["kelompok_tenure"] = pd.cut(df["tenure_months"], [0, 12, 24, 48, 72], 
                                   labels=["0-12", "13-24", "25-48", "49-72"]).astype(str) 
    return df 
  
def gaya(fig, tinggi=360): 
    fig.update_layout(template="plotly_white", height=tinggi, margin=dict(l=10, r=10, t=50, b=10), 
                      title_font_size=15, legend_title_text="") 
    return fig 
  
df = load_data() 
st.title("🔎 Exploratory Data Analysis — Customer Churn") 
st.caption("Data latihan sintetis · 3.000 pelanggan · pendaftaran Januari 2023 – Desember 2025") 
  
# ---------- KPI CARDS ---------- 
k1, k2, k3, k4, k5 = st.columns(5) 
k1.metric("Total pelanggan", f"{len(df):,}") 
k2.metric("Churn rate", f"{df.churn.mean():.1%}") 
k3.metric("Rata-rata tagihan", f"Rp{df.monthly_charges.mean():,.0f}".replace(",", ".")) 
k4.metric("Rata-rata tenure", f"{df.tenure_months.mean():.1f} bln") 
k5.metric("Missing total_charges", f"{df.total_charges_missing.sum()} baris", help="Diisi median") 
  
tab = st.tabs(["🥧 Komposisi", "📊 Perbandingan", "📈 Distribusi", "⏱️ Tren", "🔗 Hubungan", "📋 Data"]) 
  
# ---------- 1. KOMPOSISI: pie, donut, treemap ---------- 
with tab[0]: 
    c1, c2 = st.columns(2) 
    pie = px.pie(df, names="status", color="status", color_discrete_map=STATUS, 
                 title="Satu dari tiga pelanggan churn") 
    pie.update_traces(textinfo="percent+label", textfont_size=14) 
    c1.plotly_chart(gaya(pie), width="stretch") 
    donut = px.pie(df, names="contract_type", hole=0.55, color_discrete_sequence=KATEGORI, 
                   category_orders={"contract_type": KONTRAK}, 
                   title="Separuh pelanggan berkontrak bulanan") 
    donut.update_traces(textinfo="percent+label") 
    donut.add_annotation(text=f"<b>{len(df):,}</b><br>pelanggan", showarrow=False, font_size=16) 
    c2.plotly_chart(gaya(donut), width="stretch") 
    tm = df.groupby(["region", "segment"], as_index=False).agg(pelanggan=("customer_id", "count"), 
                                                              churn_rate=("churn", "mean")) 
    tree = px.treemap(tm, path=["region", "segment"], values="pelanggan", color="churn_rate", 
                      color_continuous_scale="Oranges", 
                      title="Treemap: luas = jumlah pelanggan, warna = churn rate") 
    st.plotly_chart(gaya(tree, 420), width="stretch") 
  
# ---------- 2. PERBANDINGAN: bar, grouped bar, stacked 100% ---------- 
with tab[1]: 
    kolom = st.selectbox("Bandingkan churn rate berdasarkan", 
                         ["contract_type", "region", "segment", "payment_method", "internet_service"]) 
    rk = (df.groupby(kolom, as_index=False).agg(pelanggan=("customer_id", "count"), 
                                                churn_rate=("churn", "mean")) 
            .sort_values("churn_rate"))

Prinsip konsistensi preprocessing: karena imputasi, standarisasi, dan one-hot encoding berada di dalam Pipeline,

4.3 Praktikum A — Modul inference yang dapat dipakai ulang 
Logika inference dipisahkan ke utils/model_utils.py agar dapat dipakai oleh Streamlit ( Sesi 4) maupun Dash 
(Sesi 8). Buat juga file kosong utils/__init__.py. 
 PYTHON 
"""utils/model_utils.py — fungsi bantu inference untuk Streamlit & Dash.""" 
import json 
from pathlib import Path 
import joblib 
import pandas as pd 
  
ROOT = Path(__file__).resolve().parents[1] 
MODEL_PATH = ROOT / "models" / "churn_model.joblib" 
META_PATH = ROOT / "models" / "model_metadata.json" 
  
  
def load_metadata(path=META_PATH) -> dict: 
    """Membaca kontrak input model (fitur, kategori, threshold, risk bins).""" 
    return json.loads(Path(path).read_text(encoding="utf-8")) 
  
  
def load_model(path=MODEL_PATH): 
    """Memuat final trained model (Pipeline preprocessing + classifier). Tanpa training ulang.""" 
    return joblib.load(path) 
  
  
def validate_input(df: pd.DataFrame, meta: dict) -> list[str]: 
    """Mengembalikan daftar pesan error; list kosong berarti input valid.""" 
    errors = [] 
    missing = [c for c in meta["feature_order"] if c not in df.columns] 
    if missing: 
        errors.append(f"Kolom wajib tidak ada: {missing}") 
        return errors 
    for c in meta["categorical_features"]: 
        unknown = set(df[c].dropna().unique()) - set(meta["categories"][c]) 
        if unknown: 
            errors.append(f"Nilai tidak dikenal pada '{c}': {sorted(unknown)}") 
    for c in meta["numeric_features"]: 
        if not pd.api.types.is_numeric_dtype(df[c]): 
            errors.append(f"Kolom '{c}' harus numerik") 
    return errors 
  
  
def prepare_input(df: pd.DataFrame, meta: dict) -> pd.DataFrame: 
    """Memilih & mengurutkan kolom sesuai urutan fitur saat model difinalisasi.""" 
    X = df[meta["feature_order"]].copy() 
    for c in meta["numeric_features"]: 
        X[c] = pd.to_numeric(X[c], errors="coerce") 
    return X

def risk_category(p: float, meta: dict) -> str: 
    for label, (lo, hi) in meta["risk_bins"].items(): 
        if lo <= p < hi or (hi == 1.0 and p == 1.0): 
            return label 
    return "Tidak diketahui" 
  
  
def predict(model, df: pd.DataFrame, meta: dict) -> pd.DataFrame: 
    """Menjalankan inference dan menambahkan kolom output prediksi.""" 
    X = prepare_input(df, meta) 
    proba = model.predict_proba(X)[:, 1] 
    out = df.copy() 
    out["churn_probability"] = proba.round(4) 
    out["predicted_churn"] = (proba >= meta["decision_threshold"]).astype(int) 
    out["risk_category"] = [risk_category(p, meta) for p in proba] 
    return out 
 
Penjelasan alur inference 
1. load_model() — joblib.load() mengembalikan objek Pipeline yang siap dipakai. Tidak ada .fit() di 
mana pun. 
2. validate_input() — menolak data yang kolomnya hilang atau berisi kategori yang tidak dikenal model 
(misalnya salah ketik "bulanan" huruf kecil). 
3. prepare_input() — memilih kolom dengan urutan yang sama dengan saat model difinalisasi dan 
memastikan kolom numerik bertipe angka. 
4. predict() — predict_proba(X)[:, 1] mengambil probabilitas kelas 1 (churn). Kelas prediksi ditentukan 
dengan threshold 0,5, lalu probabilitas dipetakan ke kategori risiko.

5.1 Perbedaan cara berpikir Streamlit dan Dash 
Di Streamlit, script dijalankan ulang dari atas setiap ada interaksi. Di Dash, aplikasi dibagi menjadi dua bagian yang 
terpisah tegas: 
1. Layout — pohon komponen yang mendeskripsikan tampilan. Didefinisikan sekali. 
2. Callback — fungsi Python yang dipanggil hanya ketika properti  komponen tertentu berubah, lalu 
mengembalikan nilai baru untuk properti komponen lain. 
 
Pemisahan ini membuat Dash lebih efisien untuk dashboard besar dengan banyak pengguna, karena hanya bagian 
yang terkait yang dihitung ulang.

Sesi 6 — Interactive Visualization with Plotly (90 menit) 
Sesi ini menghasilkan 13 chart interaktif Plotly (bar, pie, donut, histogram, scatter facet, line dengan  range slider, 
box, bar Graph Objects, heatmap, treemap, sunburst, funnel, dan gauge) dan menampilkannya di aplikasi Dash. 
Setiap chart diberi judul berupa insight, bukan sekadar nama variabel. 
Tujuan sesi 
• Membedakan Plotly Express (cepat, ringkas) dan Graph Objects (kontrol penuh). 
• Membuat chart interaktif dengan hover, zoom, legend toggle, dan range slider. 
• Mengatur hover dengan hover_name, hover_data, dan hovertemplate. 
• Menggunakan visual encoding: color, size, facet_col, barmode. 
• Membuat filter visual tanpa callback (legend dan updatemenus). 
• Menulis judul chart yang menyampaikan insight. 
 
6.1 Plotly Express vs Graph Objects 
Rinciannya disajikan pada Tabel 6.1. 
Tabel 6.1. Plotly Express vs Graph Objects 
Aspek Plotly Express (`px`) Graph Objects (`go`) 
Gaya Satu fungsi satu chart, input DataFrame Bangun figure dari trace satu per satu 
Panjang 
kode Pendek Lebih panjang 
Cocok untuk 90% kebutuhan dashboard Gauge/indicator, anotasi khusus, kustomisasi detail 
Contoh px.bar(df, x="region", y="churn") go.Figure(go.Bar(x=..., y=...)) 
 
Keduanya menghasilkan objek go.Figure yang sama, sehingga figure dari px tetap dapat diubah dengan 
fig.update_layout(), fig.update_traces(), fig.update_xaxes(), dan fig.add_hline(). 
6.2 Interaksi bawaan Plotly 
Setiap chart Plotly sudah interaktif tanpa kode tambahan: 
• Hover — arahkan kursor ke titik/batang untuk melihat nilai. 
• Zoom — drag area pada chart; double-click untuk kembali. 
• Legend toggle  — klik item legenda untuk menyembunyikan/ menampilkan kelompok; double -click untuk 
menampilkan hanya kelompok itu. Ini adalah filter visual paling sederhana. 
• Modebar — ikon di pojok kanan atas: unduh PNG, pan, box select, lasso select, reset.

from pathlib import Path 
import pandas as pd 
import plotly.express as px 
import plotly.graph_objects as go 
  
ROOT = Path(__file__).resolve().parents[1] 
STATUS = {"Bertahan": "#2a78d6", "Churn": "#eb6834"} 
KATEGORI = ["#2a78d6", "#1baf7a", "#eda100", "#4a3aa7", "#e87ba4"] 
KONTRAK = ["Bulanan", "Tahunan", "Dua Tahun"] 
  
  
def load(): 
    df = pd.read_csv(ROOT / "data" / "customer_churn.csv", parse_dates=["signup_date"]) 
    df["status"] = df["churn"].map({0: "Bertahan", 1: "Churn"}) 
    df["tagihan_ribu"] = df["monthly_charges"] / 1000 
    return df 
  
  
def buat_figur(df): 
    fig = {} 
    # 1. Bar chart (Plotly Express) + hover kustom 
    bar = df.groupby(["contract_type", "segment"], as_index=False)["churn"].mean() 
    bar["churn_pct"] = bar["churn"] * 100 
    f = px.bar(bar, x="contract_type", y="churn_pct", color="segment", barmode="group", 
               color_discrete_sequence=KATEGORI, category_orders={"contract_type": KONTRAK}, 
               labels={"contract_type": "Jenis kontrak", "churn_pct": "Churn rate (%)", "segment": "Segmen"}, 
               title="Kontrak bulanan memiliki churn rate tertinggi di semua segmen") 
    f.update_traces(hovertemplate="Kontrak: %{x}<br>Churn rate: %{y:.1f}%<extra></extra>") 
    fig["bar"] = f 
  
    # 2. Pie chart 
    f = px.pie(df, names="status", color="status", color_discrete_map=STATUS, 
               title="Proporsi status pelanggan") 
    f.update_traces(textinfo="percent+label", pull=[0, 0.06]) 
    fig["pie"] = f 
  
    # 3. Donut chart dengan angka di tengah 
    f = px.pie(df, names="internet_service", hole=0.55, color_discrete_sequence=KATEGORI, 
               title="Komposisi layanan internet") 
    f.add_annotation(text=f"<b>{len(df):,}</b><br>pelanggan", showarrow=False, font_size=15) 
    fig["donut"] = f 
  
    # 4. Histogram dengan warna kategori 
    fig["histogram"] = px.histogram( 
        df, x="tenure_months", color="status", nbins=36, barmode="overlay", opacity=0.7, 
        color_discrete_map=STATUS, labels={"tenure_months": "Tenure (bulan)", "status": "Status"}, 
        title="Churn terkonsentrasi pada pelanggan dengan tenure pendek") 
  
    # 5. Scatter interaktif: hover_data, facet 
    fig["scatter"] = px.scatter( 
        df, x="tenure_months", y="tagihan_ribu", color="status", color_discrete_map=STATUS, 
        hover_name="customer_id", hover_data={"region": True, "num_complaints": True, "tagihan_ribu": 
":.0f"}, 
        facet_col="contract_type", category_orders={"contract_type": KONTRAK}, opacity=0.6, 
        labels={"tenure_months": "Tenure (bulan)", "tagihan_ribu": "Tagihan (ribu Rp)"}, 
        title="Tenure vs tagihan per jenis kontrak") 
  
    # 6. Line chart tren bulanan + range slider 
    tren = (df.set_index("signup_date").groupby([pd.Grouper(freq="ME"), "status"]) 
              .size().reset_index(name="jumlah")) 
    f = px.line(tren, x="signup_date", y="jumlah", color="status", markers=True, 
                color_discrete_map=STATUS, labels={"signup_date": "Bulan pendaftaran", "jumlah": 
"Pelanggan"}, 
                title="Pelanggan baru per bulan menurut status akhir") 
    f.update_xaxes(rangeslider_visible=True) 
    fig["line"] = f 
  
    # 7. Box plot 
    fig["box"] = px.box( 
        df, x="num_complaints", y="tagihan_ribu", color="status", color_discrete_map=STATUS, 
        labels={"num_complaints": "Jumlah keluhan", "tagihan_ribu": "Tagihan (ribu Rp)"}, 
        title="Distribusi tagihan menurut jumlah keluhan")

    # 8. Graph Objects: bar dengan anotasi teks + garis referensi rata-rata 
    reg = df.groupby("region", as_index=False)["churn"].mean().sort_values("churn", ascending=False)

                                color_continuous_scale="Oranges", 
                                title="Treemap: luas = pelanggan, warna = churn rate")

    m3 = m2 & (df.num_complaints >= 2) 
    tahap = pd.DataFrame({

        "jumlah": [len(df), m1.sum(), m2.sum(), m3.sum(), (m3 & (df.churn == 1)).sum()]}) 
    f = px.funnel(tahap, x="jumlah", y="tahap", title="Funnel: penyempitan kelompok berisiko") 
    f.update_traces(marker_color="#2a78d6", textinfo="value+percent initial") 
    fig["funnel"] = f 
  
    # 13. Indicator / gauge — KPI tunggal 
    fig["gauge"] = go.Figure(go.Indicator( 
        mode="gauge+number+delta", value=df.churn.mean() * 100, number={"suffix": "%"}, 
        delta={"reference": 30, "increasing": {"color": "#e34948"}, "suffix": " pp"}, 
        title={"text": "Churn rate vs target 30%"}, 
        gauge={"axis": {"range": [0, 100]}, "bar": {"color": "#eb6834"}, 
               "threshold": {"line": {"color": "black", "width": 3}, "value": 30}})) 
  
    for f in fig.values(): 
        f.update_layout(template="plotly_white") 
    return fig

Sesi 7 — Dash Callback System (120 menit) 
Sesi ini membuat dashboard Dash benar -benar interaktif: filter mengubah KPI, chart, dan tabel; opsi dropdown

Tujuan sesi 
• Memahami anatomi callback: Input, Output, State. 
• Menulis callback dengan banyak input dan banyak output. 
• Membuat chained callback (output satu callback menjadi input callback lain). 
• Memakai State dan tombol agar callback tidak berjalan setiap ketikan. 
• Menggunakan ctx.triggered_id, PreventUpdate, no_update, dan prevent_initial_call.

7.1 Anatomi callback 
 PYTHON 
from dash import Input, Output, State, callback 
  
@callback( 
    Output("id-komponen-tujuan", "properti"),   # apa yang diperbarui 
    Input("id-komponen-pemicu", "properti"),    # apa yang memicu 
    State("id-komponen-lain", "properti"),      # dibaca, tetapi tidak memicu 
) 
def nama_fungsi(nilai_input, nilai_state): 
    ... 
    return nilai_baru_untuk_output 
 
Aturan yang harus diingat: 
1. Urutan argumen fungsi sama dengan urutan Input lalu State di dekorator. 
2. Jumlah nilai yang di-return sama dengan jumlah Output (gunakan tuple untuk lebih dari satu). 
3. Setiap pasangan Output(id, properti)  hanya boleh dimiliki satu callback (kecuali memakai 
allow_duplicate=True). 
4. Semua callback dijalankan sekali saat halaman dibuka, kecuali diberi prevent_initial_call=True. 
5. Fungsi callback harus stateless: jangan mengubah variabel global (misalnya DataFrame global), karena satu 
server melayani banyak pengguna.

Gambar 7.2. Graf callback sesi7/app_dash_callback.py 
Baca dari kiri ke kanan: komponen memicu callback, callback menulis output. Callback 3 yang disorot adalah 
callback utama dengan input dan output terbanyak. Opsi segmen dari callback 1 mengisi dropdown segmen yang 
menjadi bagian filter aktif; store keluhan dari callback 2 dibaca oleh callback 3 dan 4. 
Callback 1 — chained callback. Saat region dipilih, options dropdown segmen diperbarui sesuai region tersebut. 
Nilai segmen kemudian menjadi Input bagi callback 3 dan 4. Rantai "region → opsi segmen → pilihan segmen → 
dashboard" adalah pola umum untuk filter bertingkat (misalnya provinsi → kabupaten). 
Callback 2 — State, tombol, dan konteks. 
• in-keluhan dipasang sebagai State, sehingga mengetik angka tidak langsung memicu perhitungan. Nilai 
baru dipakai hanya saat tombol Terapkan diklik. 
• Dua tombol menjadi Input pada callback yang sama. ctx.triggered_id memberi tahu tombol mana yang 
diklik. 
• Tombol Reset mengembalikan seluruh filter ke nilai awal dengan menulis ke properti value masing-masing 
komponen. 
• Saat Terapkan diklik, hanya store-keluhan yang diubah; output lain diisi no_update agar tidak tersentuh. 
• Jika input kosong, raise PreventUpdate membatalkan update sepenuhnya. 
• prevent_initial_call=True mencegah callback berjalan saat halaman pertama kali dibuka. 
• dcc.Store menyimpan nilai keluhan yang sudah "disahkan" agar dapat dibaca callback 3 dan 4. 
 
Callback 3 — banyak Input ke banyak Output.  Lima Input (region, segmen, kontrak, tenure, store keluhan) 
menghasilkan empat Output (KPI, dua chart, teks info). Fungsi filter_df() dipisah supaya logika filter yang sama 
dipakai di callback 3 dan 4 tanpa duplikasi.

Callback 4 — interaksi chart ke tabel.  Properti clickData pada dcc.Graph berisi informasi titik yang diklik,

memfilter tabel. Jika yang memicu adalah filter lain (bukan klik chart), tabel menampilkan semua region terpilih.

def apply_filters(region, segment, kontrak, risk, tenure): 
    d = DF 
    if region: d = d[d.region.isin(region)] 
    if segment: d = d[d.segment.isin(segment)] 
    d = d[d.contract_type.isin(kontrak or []) & d.risk_category.isin(risk or [])] 
    return d[d.tenure_months.between(*tenure)]

8.4 Penjelasan keputusan desain 
• Batch inference saat start.  Karena data tidak berubah selama aplikasi berjalan, prediksi untuk 3.000 
pelanggan dihitung sekali. Callback filter hanya memotong DataFrame yang sudah berisi prediksi, sehingga 
respons tetap cepat. Untuk data yang diperbarui berkala, jalankan inference terjadwal dan simpan hasilnya 
ke file/database. 
• Donut komposisi risiko di posisi pertama  menjawab pertanyaan paling awal manajemen: berapa porsi 
pelanggan berisiko? Bar horizontal di sebelahnya langsung menunjukkan region mana yang perlu 
diprioritaskan. 
• Filter kategori risiko memakai output model.  Ini contoh prediction output yang menjadi komponen 
interaktif, bukan sekadar angka yang ditampilkan. 
• KPI "Risiko tinggi" disertai nilai tagihan bulanan berisiko  agar manajemen langsung melihat dampak 
finansial. 
• Chart aktual vs prediksi  (per kuartal dan per region) membantu pengguna menilai apakah prediksi model 
sejalan dengan kenyataan historis. 
• Garis threshold pada histogram  menjelaskan mengapa pelanggan dengan probabilitas 0,55 sudah 
diprediksi churn. 
• Tabel prioritas retensi diurutkan dari probabilitas tertinggi dengan filter bawaan DataTable, siap dipakai tim 
retensi sebagai daftar kerja. 
• Tab simulasi memakai State + tombol sehingga model hanya dipanggil saat pengguna siap, dan gauge 
berwarna sesuai kategori risiko. 
• server = app.server  disiapkan untuk deployment dengan gunicorn: gunicorn 
sesi8.app_final_dashboard:server.

@callback(Output("detail", "children"), Input("sc", "clickData")) 
def tampil_detail(click): 
    if not click: 
        raise PreventUpdate 
    cid = click["points"][0]["customdata"][0] 
    r = df.loc[df.customer_id == cid].iloc[0] 
    return html.Ul([html.Li(f"ID: {r.customer_id}"), html.Li(f"Region: {r.region}"), 
                    html.Li(f"Kontrak: {r.contract_type}"), html.Li(f"Keluhan: {r.num_complaints}")])
